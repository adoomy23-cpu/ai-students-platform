# المرحلة الثانية: التنقل والجوال وحماية عمليات الإدارة

الفرع: `feature/alfikr-navigation-mobile-v2`.
الأساس المفحوص: `design/alfikr-home-minimal` عند `d9795e335d5002ec3d791c791f986c8daa9335e9`.
بدأ العمل من ملفات نظيفة دون استبدال عمل محلي. يوجد 16 مسار صفحة فعليًا؛ لم تُحذف صفحة أو تُنشأ صفحة حساب وهمية.

## التنفيذ داخل التطبيق

### الجلسة والتنقل

- الترويسة والشعار والتذييل مشتركة. القائمة مقسمة إلى رحلة التعلّم/إدارة المنصة والحساب، دون تكرار شريط آخر لأقسام الإدارة.
- الزائر يرى الرئيسية والمحتوى والاختبارات والتحديات ودخول المعلم.
- الحساب المسجل غير المدير يرى الأقسام العامة وتسجيل الخروج، دون ادعاء أن ملف الطالب معتمد. لا توجد مسارات دخول طالب أو حسابي أو لوحة شرف أو إعدادات مستقلة؛ لم تُخترع روابط لها.
- المدير المثبت يرى أقسام الإدارة السبعة الموجودة وتسجيل الخروج. لا تظهر روابط الإدارة خلال التحميل أو التحقق أو انتهاء الجلسة أو الخطأ أو تسجيل الخروج، حتى لو بقيت نتيجة قديمة في الواجهة.
- `AuthProvider` و`access-store` يستعملان جلسة Supabase الحالية، لكن الصلاحية تأتي من استجابة خادم التطبيق بعد التحقق عبر Supabase. لا يوجد اعتماد على البريد أو بيانات الدور في metadata.
- إعادة التحقق لا تمحو مدخلات المعلم غير المحفوظة: Activity المتوفر في React 19.2 يحفظ حالة النموذج مخفية ويوقف Effects أثناء التحقق المؤقت للحساب نفسه، دون منح صلاحية أو إظهار أدوات. تُمسح الحالة عند تبديل الحساب أو الخروج أو انتهاء الجلسة أو رفض الإدارة. نوافذ التأكيد المعلقة تُلغى عند تغيّر نطاق الجلسة، ولا يستطيع حدث قديم تأكيد طلب أحدث. يلزم اختبار ذلك أيضًا في React الفعلي داخل Codespaces.
- الردود المتأخرة بعد تبديل الحساب أو الخروج أو إزالة المكوّن تُهمل. تتجدد مراجعة الصلاحية عند العودة للنافذة أو عودة الشبكة أو رفض طلب إدارة، وبمهلة واجهة لا تتجاوز 60 ثانية. كل عملية إدارة تتحقق مستقلًا على الخادم دون الاعتماد على هذه المهلة.
- تسجيل الخروج يستخدم `supabase.auth.signOut({scope:'local'})` للجهاز الحالي، ويحجب أدوات الإدارة فورًا. الخطأ أثناء الخروج لا يعيد الصلاحيات تلقائيًا.
- قائمة الجوال تغلق باختيار وجهة أو الخروج منها بالتركيز أو الضغط خارجها أو Escape؛ Escape يعيد التركيز إلى الزر. روابط عادية وأزرار أصلية مع أسماء و`aria-expanded` و`aria-controls`، دون فرض دور ARIA menu على روابط الموقع.

### حماية الإدارة

لم تكن هناك حماية مشتركة لمسارات الإدارة، وكانت صفحاتها تقرأ وتكتب عبر Supabase من المتصفح مباشرة. أُضيف:

1. `src/app/admin/layout.js` و`AdminBoundary`: لا تُركّب صفحات الإدارة ولا تبدأ طلباتها حتى ينجح تحقق الصلاحية الخادمي. صفحات الإدارة الحالية Client Components؛ لا تجلب بيانات إدارة وقت SSR. الحاجز ليس وحده أساس أمان البيانات.
2. `GET /api/account/access`: يتحقق من JWT عبر `auth.getUser(token)` ثم يستدعي `is_admin` بلا معاملات، كما في الاستدعاء الموجود في المشروع. تقبل الصلاحية الإدارية القيمة المنطقية `true` فقط؛ الاستجابة المجهولة أو خطأ الدالة لا يمنح صلاحية. لا تعاد مفاتيح أو JWT أو سجل المستخدم.
3. `POST /api/admin/operations`: يتحقق من الهوية و`is_admin` في **كل طلب قراءة أو تعديل**، قبل استدعاء الجدول أو RPC. الزائر يُرفض بـ401 وغير المدير بـ403، وفشل التحقق بـ503.
4. قائمة مغلقة من 20 عملية موجودة أصلًا: قراءة الصفوف والفصول والطلاب والمحتوى والاختبارات والتحديات والنتائج، وإضافة/تعديل/تفعيل الطلاب والفصول، وإنشاء/نشر/حذف الاختبارات، وإضافة/حذف المحتوى ومعاينة الاختبار. لا يمكن إرسال اسم جدول أو RPC أو حقل صلاحية إضافي من المتصفح.
5. عميل Supabase مستقل لكل طلب، بالمفتاح العام الحالي وJWT المتصل، دون service-role أو رفع صلاحية أو تعطيل RLS. لا يوجد عميل مشترك يحمل جلسات مستخدمين مختلفين.
6. رسائل أخطاء عامة، و`private, no-store` و`Vary: Authorization` للاستجابات. تحدد أحجام الطلبات وحقولها وأنواعها؛ يستمر الحذف الحالي خلف نافذة التأكيد الأصلية المخصصة. لم تُنفّذ أي عملية حذف أثناء العمل.
7. دعم أسماء المضيفين التي تمررها وكالات Codespaces/الاستضافة، دون اعتبار Origin أو Host إثباتًا للصلاحية؛ إثبات الصلاحية دائمًا هو JWT المحقق و`is_admin`.

نُقلت استدعاءات صفحات الإدارة السبع التي تستعمل البيانات إلى هذه البوابة، مع إبقاء الجداول وأسماء RPC وترتيب النتائج والحقول والحمولات الحالية. تشددت صفحة دخول المعلم لتقبل `is_admin === true` بدل أي قيمة truthy، دون تغيير تسجيل الدخول بكلمة المرور.

**الحماية الحية غير مكتملة التحقق:** اختبارات البوابة تُثبت سلوك شيفرة التطبيق بمحاكاة Supabase، ولا تثبت تعريف `public.is_admin()` أو سياسات RLS أو منع استدعاء Supabase مباشرة خارج التطبيق. لا نعد إخفاء الروابط أو حاجز layout إثباتًا لحماية قاعدة البيانات.

### الجوال والهوية

- الرئيسية ما زالت ترحيبًا وروبوتًا وزر استكشاف وثلاث بطاقات فقط. لا اختبارات أو أقسام مستقبلية أو لوحة معلم كبيرة فيها.
- زيدت مساحة الروبوت من 92 إلى 118 بكسل في الجوال المعتاد ومن 70 إلى 100 بكسل في الشاشات الأصغر، مع تكبير عرضه داخل إطار يقص حواف الزخرفة الخارجية؛ ملف الرسم نفسه لم يتغير. يبقى عرض الكمبيوتر عند 250/280 بكسل.
- خفض الحد الأدنى لارتفاع البطاقات إلى 76/74 بكسل على الجوال، مع هوامش أصغر وبقاء الأيقونات وأزرار اللمس واضحة. تنسيق الكمبيوتر والأجهزة اللوحية محفوظ.
- Lucide موحد، مع أيقونة خروج رسمية مرخصة. شعار المدرسة الأصلي والألوان المعتمدة والخط العربي وRTL محفوظة. لا Emoji جديدة أو alert/confirm/prompt للمتصفح في التنفيذ.

## قائمة مستقلة للفحص داخل Supabase لاحقًا

1. تعريف وتوقيع ونتيجة `public.is_admin()` الفعلية، وكيف تثبت الإدارة لحامل `auth.uid()`، وإعداد SECURITY DEFINER وsearch_path إن استُعملا. لم نخترع تعريفًا أو نعدل الدالة.
2. تعريف `get_my_student_profile` وحالات استجابتها ومعاني `approval_status` و`is_active`. الحساب غير المدير لم يُسمَّ طالبًا معتمدًا؛ استكمال هذا الربط يحتاج دليلًا من القاعدة.
3. RLS والمنح على students/grades/classrooms/quizzes/learning_content/challenges/challenge_submissions والجداول التابعة للاختبارات؛ التحقق من منع غير المدير من عمليات الإدارة عند مخاطبة Supabase مباشرة.
4. الحماية الداخلية والمنح لدوال `get_admin_quiz_results` و`get_quiz_for_student` و`get_student_directory` ودوال الإرسال. لا يُفترض أن RLS تحمي RPC من نوع SECURITY DEFINER دون فحص.
5. المسارات العامة الحالية تستخدم دليل الطلاب والاختيار اليدوي؛ يلزم فحص نطاق البيانات المتاحة لها دون كسر الاختبارات والمشاركة. لم تُغيّر هذه الوظائف تلقائيًا.
6. اختبار حي بحساب زائر وحساب طالب ومدير، وانتهاء الجلسة وسحب صلاحية المدير وظهور القوائم والرجوع والحفظ، ببيانات اختبار مخصصة.

يوجد استعلام واحد للقراءة فقط في `docs/security/inspect-supabase-read-only.sql` يستخرج بيانات المخطط والدوال والسياسات والمنح من الكتالوج، دون قراءة صفوف الطلاب. لم يُنفّذ. أي تعديل لاحق في السياسات أو المنح أو الدوال يحتاج موافقة مستقلة بعد فحص النتائج؛ لم تُكتب سياسة جديدة مفترضة.

## Codespaces

من داخل المستودع، بعد حفظ عملك المحلي:

```bash
git fetch origin && git switch feature/alfikr-navigation-mobile-v2 && git pull --ff-only origin feature/alfikr-navigation-mobile-v2 && npm run lint && npm run build && npm test && npm run dev
```

لا يثبت الأمر مكتبات أو يستبدل تغييرات محلية بالقوة، ويتوقف عند أول فشل. جرّب المقاسات 320/390/768/1440 بكسل، والروابط وTab وEscape والضغط خارج القائمة والخروج، ثم المسارات الإدارية مباشرة للزائر والطالب والمدير. فشل endpoint أو عدم توافر `is_admin` يجب أن يحجب الإدارة.
