# متابعة معالجة React Hooks

الفرع: `fix/phase1-eslint-hooks-images`، مبني على `0cde4a2`.

## سبب متابعة الإصلاح

أبلغ المستخدم عن تسعة أخطاء وتحذير واحد عند تشغيل ESLint في Codespaces.
تعذر الوصول إلى الفرع `test-phase1-fixed` عبر GitHub؛ أعاد API عدم وجود Commit
بهذا الاسم، ولم يظهر في قائمة الفروع. لم يُقرأ التقرير المحلي أو يُفترض محتواه.

## الهيكلة الحالية

- طلبات القراءة دوال مستقلة خارج المكونات، لا تحتوي على تحديث لحالة React.
- `useEffect` يبدأ الطلب فقط، ويطبق البيانات أو الخطأ داخل معالجات استجابة الشبكة.
- دوال تطبيق النتائج وإعادة التحميل من أحداث المعلم مفصولة ومثبتة بالتبعيات الصحيحة.
- لا توجد حيل `setTimeout` أو تأخير مصطنع أو تعطيل لقواعد ESLint.
- جميع التأثيرات تستخدم تنظيفًا يمنع تطبيق نتائج الطلب بعد المغادرة أو تغيير المورد.
- فشل تحميل التحديات يعرض رسالة، ولا يُعرض كأنه قائمة فارغة ناجحة.
- شملت المراجعة التأثيرات الثمانية عشر في الصفحات والمكوّن الرئيسي والنسخ الاحتياطية.

لا تغييرات في CSS أو RTL أو الاستعلامات أو عمليات إدارة المعلم. لم يُنفّذ اتصال
بقاعدة البيانات أو تعديل Supabase، ولم تُستبعد الملفات من ESLint.

## الاختبارات

أضيفت ٤٥ حالة اختبار دون اتصال للصفحات الخمس عشرة: الاستجابة، فشل الاتصال،
وتنظيف التأثير. تتحقق من عدم تحديث الحالة أثناء العرض أو تشغيل التأثير متزامنًا،
ومنع تطبيق الاستجابة بعد التنظيف. اختبارات Hooks تستخدم بدائل لا تمثل تشغيل React
داخل متصفح؛ ليست بديلًا عن ESLint أو بناء Next.

نجحت هذه الحالات واختبارات البيانات الستة، وتحليل بناء الجملة وفحص الفرق.
لم تُحاول إعادة تثبيت المكتبات. التحقق النهائي من تسعة الأخطاء والتحذير يحتاج
إلى تشغيل ESLint الفعلي في Codespaces؛ لا يُدّعى صفر أخطاء أو تحذيرات دون نتيجته.

من مجلد المشروع، دون حذف تغييرات محلية أو فرض إعادة ضبط، يمكن جلب التحديث والفحص:

```sh
git fetch origin fix/phase1-eslint-hooks-images && git switch fix/phase1-eslint-hooks-images && git pull --ff-only origin fix/phase1-eslint-hooks-images && npm run lint -- --max-warnings=0 && npm run build && npm test
```

يتوقف الأمر عند تعارض محلي أو اختلاف تاريخ الفرع أو فشل أحد الفحوص، دون تجاوزها.
